## 系统概览

todo-tui 是一个单进程终端应用，采用经典的 **MVC 变体（Model-View-Event Loop）** 架构。

```
┌──────────────────────────────────────────────────────────┐
│                     todo-tui 进程                         │
│                                                          │
│  ┌──────────────┐    ┌──────────────┐    ┌────────────┐  │
│  │  Input Layer │───▶│  App State   │───▶│ Render Layer│ │
│  │  (crossterm) │    │  (app.rs)    │    │ (ratatui)  │  │
│  └──────────────┘    └──────┬───────┘    └────────────┘  │
│                             │                            │
│                      ┌──────▼───────┐                    │
│                      │ Storage Layer│                    │
│                      │  (rusqlite)  │                    │
│                      └──────────────┘                    │
│                                                          │
└──────────────────────────────────────────────────────────┘
         ↕
   ~/.todo-tui/todos.db（SQLite 文件）
```

---

## 核心能力

| 能力 | 说明 |
|------|------|
| 终端事件驱动 | 基于 crossterm 捕获键盘事件，驱动状态机转换 |
| 响应式渲染 | 每次状态变更后重绘终端界面 |
| 数据持久化 | 通过 rusqlite 同步写入 SQLite |
| 状态机管理 | 应用模式（Normal/Add/Edit/Delete/Search/Help）由枚举状态机管理 |

## 设计原则

1. **单向数据流**：事件 → 状态变更 → 重渲染，不允许 UI 层直接修改数据
2. **存储层隔离**：所有数据库操作封装在 `storage` 模块，其他模块通过 trait 接口访问
3. **状态机明确**：应用模式用枚举表达，状态转换集中在 `app.rs` 中管理
4. **错误不 panic**：所有可恢复错误用 `Result` 传递，在 UI 层展示错误信息

## 数据流图

```
用户按键
    │
    ▼
crossterm::event::read()
    │
    ▼
app.handle_event(event)
    │
    ├── 状态转换（AppMode 变更）
    ├── 数据变更 → storage.save() → SQLite
    │
    ▼
terminal.draw(|f| ui::render(f, &app))
    │
    ▼
ratatui 渲染到终端
```
