# 检查清单 (Checklists)

> 本文档包含各阶段必须执行的检查清单。
> 所有角色在提交前必须逐条执行本文件中的检查项。

---

## 一、通用检查清单（所有角色适用）

### 1.1 提交前检查

- [ ] 代码编译通过，无错误和警告
- [ ] 所有已有测试通过
- [ ] 新增代码有对应测试覆盖
- [ ] 无硬编码的敏感信息（密码、Token、密钥）
- [ ] 无遗留的调试代码（console.log、println!、dbg! 等）
- [ ] 无注释掉的代码块
- [ ] 遵循项目代码风格（已格式化）
- [ ] 文档已同步更新（README、API 文档、架构文档）
- [ ] commit 只包含本次任务涉及的业务文件
- [ ] dispatch toml、checklist.toml、status.toml 等流程文件未进入 git
- [ ] commit message 格式正确
- [ ] 已 push 到远程

---

## 二、代码质量评审检查清单（工程师自检）

### 2.1 代码风格一致性

- [ ] 遵循项目统一的代码风格（缩进、空格、换行等）
- [ ] 使用项目配置的格式化工具（如 rustfmt、prettier）格式化代码
- [ ] 无遗留的调试代码（console.log、println!、dbg! 等）
- [ ] 无注释掉的代码块

### 2.2 命名规范

- [ ] 变量/函数/类命名清晰表达用途，无歧义缩写
- [ ] 遵循项目命名约定（camelCase、snake_case、PascalCase）
- [ ] 常量使用全大写+下划线
- [ ] 布尔变量/函数以 is/has/should/can 开头

### 2.3 错误处理完整性

- [ ] 所有可能失败的函数/方法都有错误处理
- [ ] 错误类型使用自定义错误类型而非裸字符串
- [ ] 错误信息包含足够的上下文（文件、行号、操作描述）
- [ ] 无静默吞错误（空 catch、unwrap 无注释）
- [ ] 外部输入（用户输入、API 响应、文件读取）有校验和错误处理

### 2.4 边界条件覆盖

- [ ] 空值/空集合处理
- [ ] 最大值/最小值边界
- [ ] 并发访问/竞态条件
- [ ] 超时/重试逻辑
- [ ] 资源释放（文件句柄、数据库连接、锁）

### 2.5 性能考量

- [ ] 无不必要的循环嵌套或重复计算
- [ ] 数据库查询有索引支持
- [ ] 缓存策略合理（不过度缓存也不缺失缓存）
- [ ] 大对象/大数据集避免不必要的复制
- [ ] 异步操作使用正确（无阻塞调用在异步上下文中）

### 2.6 安全合规

- [ ] 用户输入经过消毒/转义（防 XSS、SQL 注入）
- [ ] 敏感数据（密码、Token、密钥）不硬编码
- [ ] 日志中不输出敏感信息
- [ ] 权限检查在服务端而非仅客户端
- [ ] 依赖无已知高危漏洞

### 2.7 文档同步更新

- [ ] 新增/修改的 API 有接口文档更新
- [ ] 新增/修改的配置项有配置说明更新
- [ ] 架构变更（模块拆分、新增依赖）有架构文档更新
- [ ] 复杂逻辑有行内注释说明意图而非实现细节
- [ ] README/CHANGELOG 有对应更新

## 三、需求/Bug 处理检查清单

### 3.1 需求处理

- [ ] 需求已走完委派流程（N1 确认 → 总负责人 → 研发负责人 → 架构师 → 工程师）
- [ ] 需求文档已更新（REQ-XXX.md）
- [ ] 架构评审已完成（复杂需求）
- [ ] 测试用例已编写
- [ ] 实现完成后已自检

### 3.2 Bug 修复

- [ ] Bug 已确认可复现
- [ ] 根因已定位并记录
- [ ] 修复方案已评审（复杂修复）
- [ ] 修复后已验证 Bug 不再复现
- [ ] 回归测试已执行
- [ ] 修复说明已记录在 ISS-XXX.md

---

## 四、提交前检查清单（强制逐条执行）

> 所有角色在 commit 前必须逐条执行以下检查项。

### 4.1 代码完整性

- [ ] 代码编译通过，无错误和警告
- [ ] 所有已有测试通过
- [ ] 新增代码有对应测试覆盖

### 4.2 代码质量

- [ ] 无硬编码的敏感信息（密码、Token、密钥）
- [ ] 无遗留的调试代码（console.log、println!、dbg! 等）
- [ ] 无注释掉的代码块
- [ ] 遵循项目代码风格（已格式化）
- [ ] 代码质量评审检查清单（§二）已逐条自检通过

### 4.3 文档同步

- [ ] 文档已同步更新（README、API 文档、架构文档）
- [ ] 复杂逻辑有行内注释说明意图而非实现细节

### 4.4 Git 规范

- [ ] commit 只包含本次任务涉及的业务文件
- [ ] dispatch toml、checklist.toml、status.toml 等流程文件未进入 git
- [ ] 已执行 `git diff --name-only --cached` 逐一确认
- [ ] commit message 格式正确：`type(scope)[role#N]: 描述`
- [ ] 已 `git push` 到远程
