## 背景

todo-tui 当前只能通过 TUI 界面添加条目。习惯在多个终端窗口并行工作的用户，需要在不切换/打开 TUI 的情况下快速记录一条 todo。

与此同时，若 TUI 界面已在另一个终端运行，外部添加的条目不会自动出现，需要手动重启才能看到最新内容。

两项功能共同服务于「多终端并行工作」场景。技术背景：TUI 自动刷新通过轮询 DB 文件修改时间（mtime）实现，轮询间隔 500ms。

---

## 目标

1. 用户可在任意终端通过单条命令快速添加 todo 条目，无需打开 TUI 界面
2. TUI 界面运行期间能自动感知外部变化（包括 CLI 添加的条目），无需手动刷新

---

## 功能需求

### FR-1：CLI 快捷添加

**用户故事**: 作为终端用户，我希望执行 `todo-tui add <title>` 即可快速记录一条 todo，以便在不打开 TUI 的情况下随手记录任务。

**需求描述**:

**触发条件**: 用户在终端执行 `todo-tui add` 子命令。

**操作路径**:
1. 用户执行 `todo-tui add <title>`（title 为必填位置参数）
2. 系统向 `~/.todo-tui/todos.db` 写入一条新 todo 记录
3. 命令立即返回，打印一行确认信息（含新条目 ID 或标题）
4. 进程退出（exit code 0）

**可选参数**（短 flag）:
- `-p <high|medium|low>`：设置优先级，默认 medium
- `-t <tag>`：添加标签，可多次使用（如 `-t work -t urgent`）
- `-d <YYYY-MM-DD HH:MM>`：设置截止时间

**异常/边界路径**:
- title 为空字符串或未提供：命令退出并打印用法提示（exit code 1），不写入数据库
- title 过长（超过合理上限）：截断或报错，不静默截断
- `-p` 值非法（如 `-p critical`）：打印错误说明并退出（exit code 1）
- `-d` 日期格式非法：打印错误说明并退出（exit code 1）
- 数据库文件不存在：自动初始化（与 TUI 启动行为一致）
- 数据库写入失败（磁盘满/权限问题）：打印错误信息，exit code 非 0

**CLI 使用示例**:

```bash
# 最简用法（只需 title）
todo-tui add '买咖啡'

# 带优先级
todo-tui add '修复登录 bug' -p high

# 带标签
todo-tui add '整理会议纪要' -t work -t meeting

# 带截止时间
todo-tui add '提交季报' -d '2026-05-31 18:00'

# 组合使用
todo-tui add '发布 v1.2' -p high -t release -d '2026-05-20 10:00'
```

**验收标准**:
- [ ] `todo-tui add '买咖啡'` 执行后，条目立即写入数据库，命令在 200ms 内返回
- [ ] title 未提供时，exit code 为 1，不写入数据库
- [ ] `-p` / `-t` / `-d` 可选参数按说明生效
- [ ] 非法参数值打印可读错误信息，exit code 为 1
- [ ] 数据库不存在时自动初始化，不报错

**场景矩阵**:（格式见 docs/engineering/templates/scenario-matrix-template.md）

| 维度 | 场景 | 预期行为 |
|------|------|---------|
| 输入有效性 | `todo-tui add '买咖啡'`（正常 title） | 写入数据库，打印确认，exit 0 |
| 输入有效性 | `todo-tui add ''`（空 title） | 打印用法提示，exit 1，不写入 |
| 输入有效性 | `todo-tui add`（未提供 title） | 打印用法提示，exit 1，不写入 |
| 输入有效性 | `-p high`（合法优先级） | 条目以 high 优先级写入，exit 0 |
| 输入有效性 | `-p critical`（非法优先级） | 打印错误说明，exit 1，不写入 |
| 输入有效性 | `-d '2026-05-31 18:00'`（合法日期时间） | 条目以指定截止时间写入，exit 0 |
| 输入有效性 | `-d '31/05/2026'`（非法日期格式） | 打印格式错误，exit 1，不写入 |
| 前置条件/状态 | 数据库文件已存在 | 正常写入，exit 0 |
| 前置条件/状态 | 数据库文件不存在 | 自动初始化后写入，exit 0 |
| 前置条件/状态 | 数据库文件存在但无写权限 | 打印权限错误，exit 非 0，不写入 |
| 幂等性/重复调用 | 相同 title 执行两次 | 写入两条独立记录（todo 不去重），各自 exit 0 |
| 来源/优先级 | `-t work -t urgent`（多个 -t flag） | 条目携带两个标签写入，exit 0 |

**不适用维度说明**: 数量/规模边界中的「最大值/超出上限」对于 todo 条目数量不设硬上限，与 TUI 一致；title 长度上限由实现决定，需求层面要求有明确报错即可。

### FR-2：TUI 自动刷新

**用户故事**: 作为 TUI 用户，当我在另一个终端通过 CLI 添加了 todo，我希望 TUI 界面自动刷新显示最新内容，以便无需手动重启即可看到最新任务列表。

**需求描述**:

**触发条件**: TUI 界面正在运行，外部进程（如 CLI 子命令）修改了数据库文件。

**操作路径**:
1. TUI 界面运行期间，持续检测数据库文件的外部变化
2. 检测到变化后，重新从数据库加载 todo 列表
3. 刷新 TUI 显示，保持当前选中条目不变（若条目仍存在）；若当前选中条目已被删除，选中调整到合法位置
4. 刷新过程对用户透明，不中断当前操作（如正在输入的表单）

**异常/边界路径**:
- 刷新时用户正在编辑表单（Add/Edit 模式）：不中断表单，等用户完成或取消后再应用刷新
- 刷新时数据库读取失败：保持当前列表不变，不崩溃，可选显示短暂提示
- TUI 运行期间数据库文件被删除：保持当前内存中的数据，不崩溃

**验收标准**:
- [ ] CLI 添加条目后，TUI 界面在 1 秒内自动显示新条目（无需用户操作）
- [ ] 自动刷新不中断用户正在进行的 Add/Edit 操作
- [ ] 刷新后当前选中条目保持（若该条目仍存在）
- [ ] 数据库读取失败时 TUI 不崩溃

**场景矩阵**:（格式见 docs/engineering/templates/scenario-matrix-template.md）

| 维度 | 场景 | 预期行为 |
|------|------|---------|
| 输入有效性 | 外部进程写入一条新 todo | TUI 在 1 秒内刷新，新条目出现在列表 |
| 输入有效性 | 外部进程删除一条 todo | TUI 在 1 秒内刷新，该条目从列表消失 |
| 前置条件/状态 | TUI 处于 Normal 模式时触发刷新 | 列表静默刷新，选中位置保持 |
| 前置条件/状态 | TUI 处于 Add/Edit 表单模式时触发刷新 | 不中断表单，刷新延迟至表单关闭后生效 |
| 前置条件/状态 | 数据库文件被删除 | TUI 保持当前内存数据，不崩溃 |
| 前置条件/状态 | 数据库读取失败（权限变更等） | 保持当前列表，不崩溃，可选提示 |
| 幂等性/重复调用 | 短时间内多次外部写入 | 每次变化均触发刷新，最终状态与数据库一致 |

**不适用维度说明**: 来源/优先级不适用（刷新触发来源只有一种：数据库文件变化）；数量/规模边界对于刷新触发无意义。

## 不在范围

- CLI 子命令除 `add` 以外的操作（如 `list`、`done`、`delete` 等）
- TUI 界面向外推送通知（如系统通知、桌面弹窗）
- 多实例 TUI 之间的双向同步（仅单向：CLI 写 → TUI 读）
- 网络同步或云端存储
