## 背景

todo-tui 当前搜索功能（`/` 键触发，`AppMode::Search`）仅支持纯文本子串匹配，覆盖 title、tags、notes 三个字段。对于需要精确匹配、模糊模式或多关键词组合查询的用户，子串匹配表达力不足。例如用户无法通过一次搜索同时匹配"会议"和"review"，也无法使用 `^` / `$` 限定词匹配标题开头或结尾。

通过在 Search 模式内增加正则/普通切换快捷键，可在不破坏现有操作习惯的前提下为有需要的用户解锁正则能力。

---

## 目标

1. 用户可在 Search 模式内通过快捷键随时切换正则模式与普通模式
2. 正则模式下，搜索查询被解释为正则表达式，匹配范围与普通搜索相同（title、tags、notes）
3. 输入非法正则时，界面给出可读错误提示，不崩溃，不丢失用户输入

---

## 功能需求

### FR-1：正则 / 普通模式切换

**用户故事**: 作为 TUI 用户，我希望在搜索时按 `Ctrl+R` 快捷键在正则模式和普通模式之间切换，以便灵活选择搜索方式而无需退出搜索状态。

**需求描述**:

**触发条件**: 用户处于 `AppMode::Search`，按下 `Ctrl+R`。

**操作路径**:
1. 用户按 `/` 进入 Search 模式，默认为普通模式
2. 用户可直接输入搜索词进行普通子串匹配
3. 用户按 `Ctrl+R` 切换至正则模式，状态栏/搜索行出现可见的正则模式指示符（如 `[RE]`）
4. 当前输入内容保持不变，列表立即按正则模式重新过滤
5. 再次按 `Ctrl+R` 切回普通模式，指示符消失，列表按子串模式重新过滤
6. 退出 Search 模式（`ESC` 或 `Enter`）时，正则模式状态重置为关闭；下次进入搜索默认为普通模式

**异常/边界路径**:
- 搜索词为空时切换模式：允许切换，列表保持全量显示（无过滤），指示符正常切换
- 处于普通模式时搜索词为有效子串，切换至正则模式后若该子串恰好也是合法正则：按正则语义匹配（结果可能与子串匹配不同，属于预期行为）
- 多次快速连续切换：每次切换均即时响应，不积压状态

**验收标准**:
- [ ] 进入 Search 模式时默认为普通模式，状态栏无正则指示符
- [ ] 按 `Ctrl+R` 后，状态栏出现正则模式指示符，列表立即按正则重新过滤
- [ ] 再次按 `Ctrl+R`，指示符消失，列表恢复为普通模式过滤结果
- [ ] 退出 Search 模式后重新进入，模式重置为普通模式

**场景矩阵**:（格式见 docs/engineering/templates/scenario-matrix-template.md）

| 维度 | 场景 | 预期行为 |
|------|------|---------|
| 输入有效性 | 搜索词非空时按 `Ctrl+R` 切换至正则模式 | 指示符出现，列表按正则重新过滤 |
| 输入有效性 | 搜索词为空时按 `Ctrl+R` 切换 | 指示符切换，列表保持全量显示 |
| 前置条件/状态 | 在普通模式下有输入，切换至正则后再切回 | 每次切换均以当前输入重新过滤，来回切换结果可能不同 |
| 前置条件/状态 | 退出 Search 模式（ESC）后重新进入 | 正则模式重置为关闭，无指示符 |
| 幂等性/重复调用 | 连续多次按 `Ctrl+R` | 奇数次为正则模式，偶数次为普通模式，每次均响应 |

**不适用维度说明**: 数量/规模边界不适用（切换操作无数量概念）；来源/优先级不适用（切换来源唯一为 `Ctrl+R` 按键）。

### FR-2：正则匹配逻辑

**用户故事**: 作为 TUI 用户，我希望在正则模式下输入正则表达式时，搜索结果能正确匹配 title、tags、notes 中符合该正则的条目，以便精确筛选任务。

**需求描述**:

**触发条件**: 用户处于 `AppMode::Search` 且正则模式已开启，搜索词非空且为合法正则表达式。

**操作路径**:
1. 用户在正则模式下输入正则表达式（每次击键后立即重新过滤）
2. 系统将输入编译为正则表达式；默认大小写不敏感（与现有普通搜索行为一致）
3. 对每条 todo，分别在 title、tags（所有标签）、notes 三个字段中执行正则查找（任一字段匹配即保留）
4. 列表实时更新，仅显示至少一个字段匹配的条目

**异常/边界路径**:
- 搜索词为空：所有条目均显示（与普通搜索一致）
- 搜索词合法但无条目匹配：列表显示空，无错误提示
- 搜索词包含可匹配空字符串的正则（如 `.*`）：所有条目均显示
- todo 的 notes 字段为空（`None`）：该字段跳过匹配，不报错

**验收标准**:
- [ ] 正则 `^买` 仅匹配 title 以"买"开头的条目（title 精确边界匹配可用）
- [ ] 正则 `work|urgent` 能同时匹配 tags 含"work"或"urgent"的条目
- [ ] 正则匹配对 title、tags、notes 均生效，与普通搜索覆盖范围一致
- [ ] 正则匹配大小写不敏感（`TODO` 能匹配"todo"）

**场景矩阵**:（格式见 docs/engineering/templates/scenario-matrix-template.md）

| 维度 | 场景 | 预期行为 |
|------|------|---------|
| 输入有效性 | 合法正则且有匹配（如 `^买`） | 仅显示 title 以"买"开头的条目 |
| 输入有效性 | 合法正则但无匹配（如 `xyz123abc`） | 列表为空，无错误提示 |
| 输入有效性 | 可匹配任意字符串的正则（如 `.*`） | 显示全部条目 |
| 来源/优先级 | 正则匹配命中 title | 条目保留 |
| 来源/优先级 | 正则匹配命中 tags 中任意一个 | 条目保留 |
| 来源/优先级 | 正则匹配命中 notes | 条目保留 |
| 前置条件/状态 | notes 为空的条目 | 跳过 notes 字段匹配，不报错，按 title/tags 判断 |
| 幂等性/重复调用 | 相同正则多次触发过滤（快速输入删除再重输） | 结果相同，不出现不一致状态 |

**不适用维度说明**: 数量/规模边界对于正则匹配本身无独立的上下限语义；匹配上限由正则引擎处理，需求层面不设额外限制。

### FR-3：非法正则错误提示

**用户故事**: 作为 TUI 用户，当我在正则模式下输入了不合法的正则表达式时，我希望看到可读的错误提示，以便知道当前查询无效并及时修正，而不是看到空列表而不知原因。

**需求描述**:

**触发条件**: 用户处于 `AppMode::Search` 且正则模式已开启，当前搜索词无法被编译为合法正则表达式。

**操作路径**:
1. 用户在正则模式下输入内容，系统尝试编译为正则
2. 编译失败时，搜索输入行附近显示内联错误提示（如 `正则无效: unexpected end of group`）
3. 列表显示为空（因正则无效，无法过滤）
4. 用户继续修改输入，系统在每次击键后重新编译；一旦输入变为合法正则，错误提示立即消失，列表恢复正常过滤
5. 用户原始输入保持不变，不被自动修改或截断

**异常/边界路径**:
- 错误信息过长：截断显示，保证 UI 布局不被破坏
- 用户在错误状态下按 `Enter` 确认：允许退出 Search 模式，search_query 保留（但正则无效，下次进入搜索时若仍为正则模式将重新报错）
- 用户在错误状态下按 `ESC`：清空搜索词并退出 Search 模式（与现有 ESC 行为一致）
- 普通模式下任何输入均不触发此错误提示（仅正则模式生效）

**验收标准**:
- [ ] 正则模式下输入 `[未闭合`（非法正则）后，UI 出现可读错误提示，列表为空
- [ ] 在非法正则输入后补全使其合法（如补 `]`），错误提示立即消失，列表正常过滤
- [ ] 普通模式下输入任何内容（包括正则特殊字符）均不出现错误提示
- [ ] 错误提示不导致 UI 布局错乱或程序崩溃

**场景矩阵**:（格式见 docs/engineering/templates/scenario-matrix-template.md）

| 维度 | 场景 | 预期行为 |
|------|------|---------|
| 输入有效性 | 正则模式下输入合法正则 | 无错误提示，列表正常过滤 |
| 输入有效性 | 正则模式下输入非法正则（如 `[abc`） | 出现可读错误提示，列表为空 |
| 输入有效性 | 普通模式下输入含正则特殊字符（如 `[abc`） | 按字面量子串匹配，无错误提示 |
| 前置条件/状态 | 非法正则修正为合法正则（补全字符） | 错误提示立即消失，列表恢复 |
| 前置条件/状态 | 非法正则状态下按 `Enter` 退出搜索 | 退出 Search 模式，search_query 保留，不崩溃 |
| 前置条件/状态 | 非法正则状态下按 `ESC` 退出搜索 | 清空 search_query，退出 Search 模式，不崩溃 |
| 幂等性/重复调用 | 反复在合法/非法正则之间切换输入 | 每次击键均即时更新提示状态，无残留错误提示 |

**不适用维度说明**: 数量/规模边界不适用（错误提示触发与条目数量无关）；来源/优先级不适用（错误提示来源唯一为正则编译失败）。

## 不在范围

- 正则语法高亮（搜索输入框内的彩色标注）
- 保存/历史搜索记录
- 大小写敏感模式的独立开关（本需求默认大小写不敏感，与普通搜索一致）
- 搜索范围的扩展（本需求范围与现有一致：title + tags + notes，不新增字段）
- 正则替换（仅搜索，不修改数据）
