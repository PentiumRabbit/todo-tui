# 事件复盘：任務 #53 (arch) 執行失敗

## 事件摘要
- **任務**：#53 | REQ-AUTO | system → arch | 程式碼品質評審
- **狀態**：failed（循環截斷保護觸發）
- **失敗模式**：架構師連續輸出 shell 命令（ls、cat 等）讀取檔案，未委派子任務，導致對話過長被截斷

## 時間線
1. 任務 #53 被分配給 arch 角色
2. arch 啟動後，開始逐一讀取專案檔案（ls 列出目錄 → cat 讀取每個檔案）
3. 連續 shell 命令累積大量輸出，觸發循環截斷保護
4. 任務中斷，未產出任何交付物

## 根因分析

### 直接原因
架構師角色在程式碼評審任務中，選擇了「逐一讀取檔案」的線性執行模式，而非「先規劃再委派」的架構師標準流程。

### 根本原因

| 維度 | 發現 | 嚴重性 |
|------|------|--------|
| 角色 prompt 設計 | arch 角色的 prompt 未明確區分「評審」與「實現」的執行模式差異。評審任務應先規劃範圍、再委派子任務（如 eng 做程式碼掃描、arch 做結構分析），而非自己逐檔讀取 | 高 |
| 任務拆分策略 | 任務描述「程式碼品質評審」過於籠統，未拆分為可並行/串行的子任務（如：目錄結構分析、依賴分析、程式碼風格檢查、架構一致性檢查） | 高 |
| 執行模式 | arch 角色使用了 eng 角色的執行模式（shell 命令 → 讀檔案 → 分析），而非 arch 應有的模式（規劃 → 委派 → 收斂） | 中 |
| 循環截斷保護 | 保護機制本身正常運作，但未在觸發前給角色「轉向委派模式」的機會 | 低 |

### 影響範圍
- 任務 #53 失敗，需重新執行
- 下游任務（eng 實現、te 測試）延遲
- 浪費 token 在無效的 shell 命令上

## 修復建議

### [緊急] 重新執行任務 #53
- 委派 arch 角色重新執行，但 prompt 中明確要求：
  - 先規劃評審範圍（哪些目錄、哪些檔案）
  - 將評審拆為子任務（目錄結構分析、依賴分析、程式碼風格檢查）
  - 每個子任務委派給對應角色（如 eng 做程式碼掃描）
  - 自身只做結構分析和收斂

### [短期] 優化 arch 角色 prompt
- 在 arch 角色規則中增加：
  - 「評審任務禁止逐檔讀取，必須先規劃範圍再委派」
  - 「連續 shell 命令超過 5 次後必須轉向委派模式」
  - 「評審任務的預設執行模式：規劃 → 委派 → 收斂，而非 shell → 讀取 → 分析」

### [長期] 任務拆分模板
- 為常見任務類型（評審、實現、測試）建立標準拆分模板
- 評審任務模板：
  1. 範圍規劃（arch 自身）
  2. 目錄結構分析（委派 eng）
  3. 依賴分析（委派 eng）
  4. 程式碼風格檢查（委派 eng）
  5. 架構一致性檢查（arch 自身）
  6. 收斂報告（arch 自身）
